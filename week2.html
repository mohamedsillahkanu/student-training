csv, the plain text table

➤ explaining this now

A csv is a text file with commas between the values. Anything can open it, which is why it is the format you will meet most, and why it arrives in every possible state.

package: readr, part of the tidyverse

Type this

12library(tidyverse) cases <- read_csv("routine_cases_dummy.csv")

The everyday one. read_csv guesses each column type and tells you what it chose.

Five cases you will actually meet

Each one is a situation you will meet, with the answer and the line of R that fixes it.

1Your chiefdom codes have lost their leading zeros: 0450 is now 450.

R saw digits and made the column a number. Read it as text: col_types = cols(chiefdom_code = col_character()). Do it at reading time, never afterwards, because the zero is gone once it is a number.

12read_csv("routine_cases_dummy.csv", col_types = cols(chiefdom_code = col_character()))
2A whole column that should be numbers came in as text.

Something non numeric is hiding in it: a comma in 1,249, a stray dash, or the word NA spelled differently. Run count(cases, suspected) and look at the odd values, then clean them with the na argument or fix them in the source.

1count(cases, suspected) # look at the odd values first
3The file opens fine in Excel but read_csv gives one giant column.

It is separated by semicolons, which is normal in French and Portuguese locales. Use read_csv2, which expects semicolons and a comma as the decimal mark.

1read_csv2("routine_cases_dummy.csv") # semicolon separated
4Accented district names show as strange symbols.

The file is not UTF-8. Read it with read_csv(file, locale = locale(encoding = "Latin1")) and the accents come back.

12read_csv("routine_cases_dummy.csv", locale = locale(encoding = "Latin1"))
5R says the file does not exist, but you can see it in the folder.

You are in a different folder from the one you are looking at, or Windows is hiding the real extension and the file is actually .csv.txt. Run list.files() and use the name exactly as it prints.

1list.files() # then use the name exactly as it prints

Excel workbooks

➤ explaining this now

Excel files hold several sheets, merged cells, and headers that start halfway down the page. readxl reads them without needing Excel installed.

package: readxl

Type this

12library(readxl) cases <- read_excel("routine_cases_dummy.xlsx")

The first sheet, assuming row one is the header.

Five cases you will actually meet

Each one is a situation you will meet, with the answer and the line of R that fixes it.

1Your dates have become numbers like 45231.

That is Excel's day count. readxl usually converts it, but not when the column is mixed. Convert with as.Date(45231, origin = "1899-12-30"), and note the origin: Excel thinks 1900 was a leap year.

1as.Date(45231, origin = "1899-12-30")
2The first rows are a logo and a title, so every column is text.

The header was read from the wrong row. Use skip to jump the title block, or read the exact rectangle with range.

1read_excel("routine_cases_dummy.xlsx", skip = 3)
3Merged cells leave gaps in the district column.

Only the first row of a merge holds the value. Read it, then fill downwards with tidyr::fill(cases, district).

12library(tidyr) cases <- fill(cases, district)
4You get "Error: path does not exist" on a file you just downloaded.

It is still in Downloads, not your project folder, or the name has (1) in it from a second download. Check with list.files() and move it into the project.

1list.files() # find the real name, then move the file into your folder
5The numbers look right but every total is wrong.

Some cells are text that looks numeric, often with a trailing space. Check with sapply(cases, class), then convert with as.numeric(trimws(column)).

1cases$suspected <- as.numeric(trimws(cases$suspected))

Stata files (.dta)

➤ explaining this now

Stata files carry labels: the value 1 might be labelled Yes. haven keeps those labels, which is useful once you know they are there and confusing until you do.

package: haven

Type this

12library(haven) mis <- read_dta("mis_household_extract.dta")

Read the file. Labelled columns arrive as a labelled type, not plain numbers.

Five cases you will actually meet

Each one is a situation you will meet, with the answer and the line of R that fixes it.

1Your urban and rural column prints as 1 and 2.

They are labelled values. as_factor(mis) turns the whole dataset into readable words, or haven::as_factor(mis$hv025) for one column.

1mis <- as_factor(mis)
2ggplot refuses to plot a labelled column.

It is a haven_labelled type, not a number or a factor. Convert it first with as_factor for categories or as.numeric for measurements.

1mis$hv025 <- as_factor(mis$hv025) # or as.numeric() for a measurement
3Survey weights are enormous, in the millions.

DHS weights are stored multiplied by a million. Divide by 1e6 before using them, which is in the survey documentation and catches everyone once.

1mis$weight <- mis$hv005 / 1e6
4The file is 400MB and R runs out of memory.

Read only what you need with col_select, and filter early. You rarely need all 5,000 columns of a DHS recode file.

12read_dta("mis_household_extract.dta", col_select = c(hv001, hv005, hv025))
5A column of dates is a strange number.

Stata counts days from 1960. Convert with as.Date(value, origin = "1960-01-01").

1as.Date(mis$interview_date, origin = "1960-01-01")

SPSS files (.sav)

➤ explaining this now

SPSS files are labelled like Stata files, and read with the same package. The differences are in the details: missing value codes and long variable labels.

package: haven

Type this

12library(haven) survey <- read_sav("routine_cases_dummy.sav")

Read the file, labels and all.

Five cases you will actually meet

Each one is a situation you will meet, with the answer and the line of R that fixes it.

1Codes 97, 98 and 99 are being averaged into your results.

They are missing value codes for refused, do not know and not applicable. Read with user_na = TRUE, then set them to NA before any calculation.

1survey <- read_sav("routine_cases_dummy.sav", user_na = TRUE)
2Your column names are q1, q2, q3 and mean nothing.

The meaning is in the labels, not the names. Print them with sapply(survey, function(x) attr(x, "label")) and rename the ones you use.

1sapply(survey, function(x) attr(x, "label"))
3as_factor produces categories that are not in the data.

SPSS keeps every defined label, used or not. Drop the empty ones with droplevels().

1survey <- droplevels(as_factor(survey))
4Text answers come out garbled.

The file uses an older encoding. Try read_sav(file, encoding = "latin1").

1read_sav("routine_cases_dummy.sav", encoding = "latin1")
5The same variable is numeric in one file and text in another.

Two rounds of the same survey, coded differently. Force the type at reading time so both match before you bind them together.

1read_sav("round2.sav") |> mutate(age = as.numeric(age))

GeoJSON boundaries

➤ explaining this now

A GeoJSON holds shapes as well as a table: one row per district, with a geometry column holding its outline. sf treats it as a data frame that happens to have a map in it.

package: sf

Type this

12library(sf) chiefdoms <- st_read("chiefdoms_sl.geojson")

Read it. The message tells you how many features and which coordinate system.

Five cases you will actually meet

Each one is a situation you will meet, with the answer and the line of R that fixes it.

1Your map is empty, or the shapes are in the sea near Africa.

The coordinate system is missing or wrong, so the coordinates are being read as degrees when they are metres. Check st_crs, then st_set_crs if it is missing or st_transform if it is simply different.

12st_crs(chiefdoms) chiefdoms <- st_transform(chiefdoms, 4326)
2A join to your case data matches nothing.

The names differ: "Western Area Urban" against "Western Urban", or a trailing space. Compare with setdiff(chiefdoms$name, cases$district) and fix the join key, never the geometry.

1setdiff(chiefdoms$name, cases$district)
3Every dplyr verb drags the geometry along and is slow.

That is by design. Use st_drop_geometry() when you only need the table, and keep the shapes for the map at the end.

1chiefdoms |> st_drop_geometry() |> count(district)
4The file is 200MB and plotting takes minutes.

It is far more detailed than any map needs. Simplify with st_simplify(x, dTolerance = 100), in the units of the coordinate system.

1chiefdoms <- st_simplify(chiefdoms, dTolerance = 100)
5summarise() gives you one enormous shape.

sf unions the geometries by design. That is how you dissolve chiefdoms into districts, and a surprise if you did not want it.

1chiefdoms |> group_by(district) |> summarise() # dissolves on purpose

Shapefiles (.shp)

➤ explaining this now

A shapefile is not one file. It is at least three that must sit together, and it is the format most likely to arrive incomplete.

package: sf

Type this

12library(sf) sl <- st_read("sl_districts.shp")

Name the .shp, but the .shx, .dbf and .prj must be beside it.

Five cases you will actually meet

Each one is a situation you will meet, with the answer and the line of R that fixes it.

1"Cannot open data source" on a file that is definitely there.

One of the companion files is missing, usually the .shx or .dbf. A shapefile needs .shp, .shx and .dbf together, with .prj strongly advised. Ask for the whole zip again.

1list.files(pattern = "sl_districts") # .shp .shx .dbf .prj must all be there
2The shapes line up wrongly against your other layer.

No .prj file, so the coordinate system is unknown and R has guessed. Get the .prj, or set it with st_set_crs once you know what it should be.

1sl <- st_set_crs(sl, 4326) # only when you know what it should be
3Column names are cut to ten characters: chiefdom_code became chiefdom_c.

That is a hard limit of the format, not a bug. Rename after reading, and prefer GeoPackage or GeoJSON when you are the one saving.

1names(sl)[names(sl) == "chiefdom_c"] <- "chiefdom_code"
4The names are UPPERCASE in one file and Title Case in another.

Normalise before joining: mutate(name = str_to_title(str_trim(name))) on both sides, then join.

1sl$name <- stringr::str_to_title(stringr::str_trim(sl$name))
5You were sent a zip and are not sure what to do with it.

unzip("boundaries.zip", exdir = "boundaries") then st_read on the folder. Do not read from inside the zip: sf needs the files side by side on disk.

12unzip("boundaries.zip", exdir = "boundaries") sl <- st_read("boundaries")

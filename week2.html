Bar charts in R

Three ways to draw one, each from install.packages to a saved file, with the output after every line

Goal 1 Know the three ways to make a bar chart one category, one number, one of each
Goal 2 Know which line causes which part of the picture every step shows its output
Goal 3 Change a chart you have already drawn, when somebody asks for it differently sort it, turn it sideways, split it by month, label the bars

Bar chart: one bar for each category, as long as the number it stands for. Districts, chiefdoms, months, age groups: anything you can count.

A ggplot chart is layers joined with a plus sign. Each line adds one thing, and you can see exactly what it added.

A bar chart always needs two kinds of thing: something to make the bars out of, and something to decide how tall they are. Those are the two kinds of column in your data.

Categorical variable

A column of names or labels. R marks it <chr>. You can count how often each value appears, but you cannot add them up.

In this file: district (Kailahun, Bo, Kenema), month (January, February), chiefdom (Dea, Malema), facility (Dea CHC).

This decides how many bars you get and what they are called.

Numeric variable

A column of measurements. R marks it <dbl>. You can add these, average them and compare them.

In this file: confirmed (33, 44, 52), suspected (136, 129, 138), tested_rdt (112, 108, 117).

This decides how tall the bars are.

Look at your two columns, decide which kind each one is, and that single question tells you which of the three ways to use. All three are built below, from install.packages to a saved file, with the output after every line.

A categorical column holds names or labels. In this file that is district, chiefdom, facility and month, and R marks them <chr> for character. You can count how many times each value appears, but you cannot add them up: Kailahun plus Bo is not a number. In a bar chart a categorical column decides how many bars you get, and what they are called.

A numeric column holds measurements. Here that is suspected, tested_rdt and confirmed, marked <dbl> for double, which is R saying a number that can have decimals. You can add these, average them and compare them. In a bar chart a numeric column decides how tall the bars are.

So before you write any chart code, look at your two columns and ask which kind each one is. That single question picks the way for you: one categorical column, one numeric column, or one of each.

Watch out

Be careful with a numeric column that is really a label. year and chiefdom_code arrive as <dbl>, but nobody wants the average chiefdom code. Wrap those in factor() and treat them as categories.

The three ways to a single bar chart

no group_by anywhere

Which way you use is decided by one thing: which columns you have. One category, one number, or one of each. Each way below runs from install.packages to a saved file, so you can follow whichever one matches your data without reading the others. None of them needs a group_by.

3

Goal 3: change a chart you have already drawn

five before and after examples

Your chart is drawn and somebody asks for it differently. Each of these five shows the code you have now, then the same code with the change marked, and the chart it produces. Decide which line you would touch before you open the answer.

Use case scenario 1

My chart has one bar per district in alphabetical order, and my supervisor wants them biggest first. What changes?

the code you have now
ggplot(cases, aes(x = district, y = confirmed)) + geom_bar(stat = "summary", fun = sum, fill = "steelblue") + theme_minimal()

change it to this

the same code, with the change marked
ggplot(cases, aes(x = reorder(district, -confirmed), y = confirmed)) + geom_bar(stat = "summary", fun = sum, fill = "steelblue") + theme_minimal()
R plot windowplot

One line changes, and only inside aes(). reorder() wraps the column you are sorting; the minus sign gives biggest first, and without it you get smallest first.

Use case scenario 2

The district names overlap along the bottom and cannot be read. What changes?

the code you have now

4

Common mistakes

the three that cost the most time

geom_bar() against geom_col()

Plain geom_bar() counts rows and ignores y. geom_col() uses y but adds nothing up, so a district with 114 rows becomes 114 stacked slices. The one that turns many rows into one bar is geom_bar(stat = "summary", fun = sum), which is why this module uses it and never needs a group_by.

fill inside aes() against outside it

fill = "steelblue" goes OUTSIDE aes(), because it is one fixed colour. fill = month goes INSIDE aes(), because the colour comes from the data. Put the quoted colour inside aes() and ggplot treats "steelblue" as a category, giving you one salmon coloured bar and a legend saying steelblue.

the plus sign at the end of the line

Every layer joins with + at the END of the previous line, never at the start of the new one. A + at the beginning is where R stops and says unexpected symbol.

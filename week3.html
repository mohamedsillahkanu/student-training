Why a name with symbols breaks things

➤ explaining this now

A column called Total Amount ($) is perfectly readable to a person and painful to R. You cannot write cases$Total Amount ($) without quoting and backticks, the dollar sign means something else in R, and the same name arrives spelled three different ways from three facilities. The poster below is the whole of this module in one picture: the characters to remove, names before and after, values before and after, and the code in three tools.

Type this line

1names(cases)
R consoleOUTPUT
[1] "Customer ID#"      "Order Date (MM/DD)" "Total Amount ($)"
[4] "% Discount"        "Status*"            "Product-Name!"
What that line did

names() prints the column names exactly as they are. Read that list before you write anything else: every problem in this module is visible in it.

Five cases you will actually meet

Each one is a situation you will meet, with the answer and the line of R that fixes it.

1R says "object Total not found" when you type cases$Total Amount ($).

The space ends the name, so R read Total and stopped. Either use backticks around the whole name, or clean the names once and stop fighting it.

12cases$`Total Amount ($)` # works, but ugly clean_names(cases) # better
2The same column is Customer ID# in one file and customer_id in another.

Two facilities, two habits. Clean both files the same way and the names match, which is what lets you bind them together.

123a <- clean_names(a) b <- clean_names(b) bind_rows(a, b)
3Your column names came in as ...1, ...2, ...3.

The header row was empty or missing, so R made names up. Read the file again with the right header row rather than renaming these.

1read_csv("routine_cases_dummy.csv", skip = 2)
4A name has a line break in it from Excel.

It looks like one word on screen and is two lines underneath. clean_names removes it along with everything else.

1cases <- clean_names(cases)
5You want to see the problem names before you change anything.

Print them. Every problem in this module is visible in that one list.

1names(cases)

Clean every column name with one line

➤ explaining this now

janitor::clean_names does the whole job at once: it strips the symbols, turns spaces into underscores, and puts everything in lower case, so every name in your data follows one rule. This is the one line to remember from this module.

Type this line

123library(janitor) cases <- clean_names(cases) names(cases)
R consoleOUTPUT
[1] "customer_id"    "order_date_mm_dd" "total_amount"
[4] "percent_discount" "status"        "product_name"
What that line did

Notice what it did to % Discount: it became percent_discount, because janitor knows that % means percent and keeps the meaning rather than deleting it. Run it once, straight after reading the file, and every line you write afterwards is simpler.

Five cases you will actually meet

Each one is a situation you will meet, with the answer and the line of R that fixes it.

1clean_names gives you percent_discount, not discount.

That is deliberate: janitor writes the word rather than deleting the meaning. Rename it afterwards if you would rather have discount.

1cases <- rename(cases, discount = percent_discount)
2You want dots instead of underscores, to match an old script.

clean_names takes a case argument, so you do not have to write your own cleaner.

1cases <- clean_names(cases, case = "snake") # or "lower_camel", "old_janitor"
3Two columns end up with the same name after cleaning.

They were different only by punctuation. janitor adds a number so nothing is silently lost: check which is which and rename.

1names(cases) # look for total_amount and total_amount_2
4You do not want to install janitor on a locked-down machine.

One line of stringr does most of it, though you lose the percent handling.

1names(cases) <- str_replace_all(names(cases), "[^A-Za-z0-9]+", "_")
5Your names are now lower case and your old script uses capitals.

Change the script once, not the data every time. Consistent lower case is worth the one edit.

1cases$total_amount # the new way, everywhere

Clean the values inside a column

➤ explaining this now

Names are only half of it. In stock!!! and In stock are two different values to R, so they count as two different things. Strip the punctuation from your text columns and the counts come back together.

Type this line

123cases <- cases |> mutate(across(where(is.character), ~ str_replace_all(.x, "[^A-Za-z0-9 ]", "")))
R consoleOUTPUT
# before:  "In stock!!!"  "In stock"   "Pre-order #1"
# after:   "In stock"     "In stock"   "Preorder 1"
What that line did

across(where(is.character)) means every text column, so you do not name them one by one. The square brackets say keep letters, numbers and spaces, remove everything else. Two spellings of In stock become one, and your counts are right again.

Five cases you will actually meet

Each one is a situation you will meet, with the answer and the line of R that fixes it.

1count() shows In stock three times.

Three spellings: with exclamation marks, with a trailing space, and clean. Strip the punctuation and trim the spaces and they become one.

1cases <- mutate(cases, remarks = str_squish(str_replace_all(remarks, "[^A-Za-z0-9 ]", "")))
2After cleaning, two values still look identical but count separately.

One has a double space inside it, which you cannot see. str_squish collapses runs of spaces and trims the ends.

1cases <- mutate(cases, remarks = str_squish(remarks))
3Some values are UPPER CASE and some are Title Case.

Case matters to R. Put the whole column in one case as part of cleaning.

1cases <- mutate(cases, remarks = str_to_lower(remarks))
4A district name has an accent and will not match your boundary file.

Do not delete the accent, translate it, so the name stays readable and matches.

1cases <- mutate(cases, district = stringi::stri_trans_general(district, "Latin-ASCII"))
5Empty cells became "" instead of NA after cleaning.

An empty string is not missing to R. Turn the blanks back into NA before you count anything.

1cases <- mutate(cases, remarks = na_if(str_squish(remarks), ""))

Do not remove the meaning

➤ explaining this now

This is where people go too far. A minus sign in front of a number, a decimal point, the dash in a date, the plus in Samsung Galaxy S24+: strip those and you have not cleaned the data, you have damaged it. Clean the labels, leave the measurements alone.

Type this line

123cases <- cases |> mutate(across(c(product_name, remarks), ~ str_replace_all(.x, "[^A-Za-z0-9 ]", "")))
R consoleOUTPUT
# only the two columns named are touched
# confirmed, reporting_date and any number keep every character they had
What that line did

Naming the columns is safer than sweeping every one. If you do sweep them all, do it before you convert anything to a number or a date, and look at the result.

Five cases you will actually meet

Each one is a situation you will meet, with the answer and the line of R that fixes it.

1Your negative numbers lost their minus sign.

The sweep hit a numeric column. Only clean text columns, and never after converting to a number.

1mutate(across(where(is.character), ~ str_replace_all(.x, "[^A-Za-z0-9 ]", "")))
2Dates like 05/01/2024 became 05012024.

The slashes were part of the meaning. Exclude the date column, or convert it to a date first so it is no longer text.

1mutate(across(c(product_name, remarks), ~ str_replace_all(.x, "[^A-Za-z0-9 ]", "")))
3Samsung Galaxy S24+ became Samsung Galaxy S24.

The plus was part of the product name. Keep the characters you need by adding them inside the brackets.

1str_replace_all(product_name, "[^A-Za-z0-9 +]", "")
4Decimal points disappeared and 250.00 became 25000.

Same mistake, worse consequence. Numbers should never go through a text cleaner.

1cases <- mutate(cases, total_amount = as.numeric(total_amount))
5You are not sure which columns are text.

Ask before you sweep. glimpse marks every column chr or dbl.

1glimpse(cases)

Check what you changed

➤ explaining this now

Cleaning is easy to get wrong quietly. Two lines tell you whether it worked: print the names, and count the values of the column you cleaned. If a category you expected has vanished or split, you will see it here rather than in your results.

Type this line

12names(cases) count(cases, remarks, sort = TRUE)
R consoleOUTPUT
# 1 "customer_id" "order_date_mm_dd" ...

# remarks          n
# In stock       412
# Best seller    108
# Preorder 1      37
What that line did

Names in one rule, and each value appearing once instead of three times. That is what finished cleaning looks like. Do this before you build any table, not after somebody questions your numbers.

2A category you expected has disappeared entirely.

It was probably an empty string, or it merged into another value. Count before and after and compare the two.

1count(cases, remarks, sort = TRUE)
3Your totals changed after cleaning.

A numeric column was swept. Read the module again from card 4, and reload the file to start from the original.

1cases <- read_csv("routine_cases_dummy.csv")
4You want to prove to a colleague what changed.

Keep the original alongside and show the two lists of names.

12raw <- read_csv("routine_cases_dummy.csv") data.frame(before = names(raw), after = names(clean_names(raw)))

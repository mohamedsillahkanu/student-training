When to use it

Whenever a question is about part of the data: one district for a review meeting, one month for a bulletin, or the facilities above a threshold you want to visit.

How to use it

filter() keeps rows where a condition is TRUE. Use == to match, > and < to compare, %in% for a list, is.na() for gaps, and commas or | to combine.

What happensillustration

1One value

bo <- cases %>% filter(district == "Bo") nrow(bo) bo %>% select(chiefdom, month, confirmed) %>% head(3)
R Consoleoutput
[1] 102

# A tibble: 3 x 3
  chiefdom month    confirmed
  <chr>    <chr>        <dbl>
1 Badjia   January         92
2 Badjia   February       107
3 Badjia   March          108
Explanation
  • == is a test for equality; a single = would try to assign and error.
  • Text goes in quotes, and it is case sensitive: "bo" would not match "Bo".
  • 102 rows for a district with 17 chiefdoms is 17 times 6 months, so the filter did what you expected.

2A comparison

cases %>% filter(confirmed > 150) %>% nrow() cases %>% filter(suspected >= 350) %>% select(district, chiefdom, month, suspected) %>% head(3)
R Consoleoutput
[1] 32

# A tibble: 3 x 4
  district chiefdom    month suspected
  <chr>    <chr>       <chr>     <dbl>
1 Kono     Gorama Kono April       375
2 Kono     Toli        April       357
3 Bombali  Makeni City April       355
Explanation
  • >, >=, < and <= work on any numeric column.
  • Rows where the column is NA are dropped by a comparison, because R cannot say whether an unknown value is above 150.
  • Eight facility months clear 350 suspected cases and every one of them is in April, the seasonal peak, visible without any analysis. filter() keeps them in file order, so these are the first three, not the largest three.

3More than one condition

# both must be true, use a comma, or & cases %>% filter(district == "Bo", month == "April") %>% nrow() # either one, use | cases %>% filter(district == "Bo" | district == "Kenema") %>% nrow() # one of several, use %in% cases %>% filter(month %in% c("January", "February")) %>% nrow()
R Consoleoutput
[1] 17

[1] 203

[1] 416
Explanation
  • A comma between conditions means AND: 17 chiefdoms in Bo, one row each for April.
  • | means OR. Writing district == "Bo" | "Kenema" is a common error and does not do what it looks like.
  • %in% is the readable way to test against a list, and it scales to twenty values without twenty | signs.

4Ranges and missing values

cases %>% filter(between(suspected, 100, 150)) %>% nrow() cases %>% filter(is.na(tested_rdt)) %>% select(district, chiefdom, month, tested_rdt)
R Consoleoutput
[1] 282

# A tibble: 1 x 4
  district chiefdom     month    tested_rdt
  <chr>    <chr>        <chr>         <dbl>
1 Kailahun Kpeje Bongre February        NA
Explanation
  • between(x, 100, 150) includes both ends and reads better than two conditions.
  • is.na() is the only way to find missing values, tested_rdt == NA returns NA for every row and keeps nothing.
  • filter(!is.na(tested_rdt)) with the exclamation mark does the opposite: every row that does have a value.

5Filter and select together

april_bo <- cases %>% filter(district == "Bo", month == "April") %>% select(chiefdom, suspected, tested_rdt, confirmed) head(april_bo, 4)
R Consoleoutput
# A tibble: 4 x 4
  chiefdom       suspected tested_rdt confirmed
  <chr>              <dbl>      <dbl>     <dbl>
1 Badjia            211        154        57
2 Bagbo             255        222       113
3 Bagbwe (bagbe)    269        213        84
4 Boama             225        172       109
Explanation
  • Rows first, then columns: the order does not change the answer, but filtering first means select() works on less data.
  • Assigning the result to a name gives you a small table to work with, while cases stays whole.
  • This is the shape of nearly every real request: one district, one month, four columns.

The ten mistakes Part 2 covers

Read this table once before you start. Every broken snippet below is one of these ten, so nothing in Part 2 is something you have not been shown, the work is spotting which mistake it is and correcting it yourself.

What people writeWhat it should beWhy
1cases %>% subset(district == "Kenema")cases %>% filter(district == "Kenema")subset() is base R and behaves differently inside functions. The dplyr verb is filter().
2cases %> filter(district == "Kenema")cases %>% filter(district == "Kenema")The pipe is three characters: %>%. Anything else is a syntax error.
3cases %>% filter(tested_rdt == NA)cases %>% filter(is.na(tested_rdt))Nothing equals NA, not even NA itself, so this returns NA rather than TRUE or FALSE. Test with is.na().
4cases %>% filter(district = "Kenema")cases %>% filter(district == "Kenema")One equals sign assigns; two compare. Inside filter() a single = is read as naming an argument, and R errors.
5cases %>% filter(district == Kenema)cases %>% filter(district == "Kenema")A value in a column is text, so it needs quotes. Without them R looks for an object with that name, object not found.
6cases %>% filter(month in c("January", "February"))cases %>% filter(month %in% c("January", "February"))The operator is %in% with a percent sign either side. Bare in only works inside a for loop.
7cases %>% Filter(district == "Kenema")cases %>% filter(district == "Kenema")R is case sensitive: Filter() does not exist. It is filter(), all lower case.
8cases %>% filter(district == "Kenema"cases %>% filter(district == "Kenema")A bracket is missing. R waits for the rest of the line and shows a + prompt instead of an answer: count the brackets.
9cases %>% subset(confirmed > 150)cases %>% filter(confirmed > 150)subset() is base R and behaves differently inside functions. The dplyr verb is filter().
10cases %> filter(confirmed > 150)cases %>% filter(confirmed > 150)The pipe is three characters: %>%. Anything else is a syntax error.

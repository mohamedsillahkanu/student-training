When you are ready to plot

Every time you plot anything. A bar chart needs exactly one number per category, so if your data still has 1,249 rows you are not ready to plot.

How to get there

Read with read_csv(), clean the labels with mutate(), drop the duplicate with distinct(), then collapse to one row per category with group_by() and summarise(), or count() if you only need rows.

What happensillustration

A bar chart is the last step, not the first

Nothing in this module plots raw data. A bar chart shows one number per category, so the work happens before ggplot() is ever called: read the file (Week 1), clean the labels, keep the rows you want, and collapse 1,249 records into one row per district or per month (Modules 2 to 6). The chart is three lines at the end.

Every plot in this module has the same three parts

ggplot(data, aes(x = ..., y = ...)) says what maps to what, geom_col() says draw it as bars, and labs() puts the words on. Everything else on the following cards, ordering, flipping, grouping, stacking, faceting, colouring, is a variation on those three lines.

Why only bar charts

Bars are what routine malaria reporting actually needs: cases by district, cases by month, ITNs by chiefdom, this quarter against last. One chart type done properly beats five done badly, and every trick you learn here, ordering, labelling, faceting, saving: carries straight over to lines and boxplots later.

When to use it

Every bar chart is one of these two. Use geom_col() when you already have a total; use geom_bar() when you want ggplot2 to count the rows itself.

How to use it

geom_col() needs x and y. geom_bar() needs only x, it puts the count on the y axis. geom_bar(stat = "identity") is the old way of writing geom_col().

What happensillustration

1geom_col: you supply the height

ggplot(top6, aes(x = district, y = confirmed)) + geom_col(fill = "steelblue") + labs(x = NULL, y = "Confirmed cases")
Plots panefigure
Explanation
  • geom_col() takes the number in y as the height of the bar. Nothing is calculated.
  • fill sets the inside colour and colour sets the outline. Put them outside aes() when the colour is fixed rather than driven by data.
  • Bars come out in alphabetical order because district is text: the next card fixes that.

2geom_bar: ggplot2 counts the rows

ggplot(cases, aes(x = district)) + geom_bar(fill = "steelblue") + labs(x = NULL, y = "Number of records")
Plots panefigure
Explanation
  • Only x is mapped. geom_bar() counts how many rows fall in each district and uses that as the height.
  • This is a chart of reporting volume, not of cases: Tonkolili is tallest because it has the most chiefdoms, 19.
  • Mapping y as well is the commonest ggplot2 error of all, it gives Error: stat_count() must not be used with a y aesthetic.

3The old spelling: geom_bar(stat = "identity")

ggplot(top6, aes(x = district, y = confirmed)) + geom_bar(stat = "identity", fill = "steelblue") + labs(x = NULL, y = "Confirmed cases")
Plots panefigure
Explanation
  • stat = "identity" tells geom_bar() to leave the numbers alone, which makes it behave exactly like geom_col().
  • Identical output. You will meet this form in older code and on the internet constantly, so recognise it.
  • Write geom_col() in your own work: it says what it does in one word.

4Bars sideways, without coord_flip

ggplot(top6, aes(x = confirmed, y = district)) + geom_col(fill = "steelblue") + labs(x = "Confirmed cases", y = NULL)
Plots panefigure
Explanation
  • Swap the mappings: the category on y, the number on x, and the bars lie down. No extra function is needed in modern ggplot2.
  • Horizontal bars are the right choice whenever the category labels are long, which in Sierra Leone means chiefdom names almost always.
  • The old way was coord_flip(), which the next card also shows because you will see it everywhere.

5Width, outline and transparency

ggplot(by_month, aes(x = month, y = confirmed)) + geom_col(width = 0.6, fill = "steelblue", colour = "black", alpha = 0.85) + labs(x = NULL, y = "Confirmed cases")
Plots panefigure
Explanation
  • width runs from 0 to 1, where 1 leaves no gap at all. Around 0.6 to 0.8 reads best in a report.
  • colour outlines each bar and alpha makes the fill semi transparent. Both are cosmetic and both are set outside aes().
  • If you find yourself putting a fixed colour inside aes(), ggplot2 will draw a legend for a colour that means nothing, that is the tell.

When to use it

Any bar chart of a text category. Unordered bars make the reader compare heights by eye across the whole chart; ordered bars answer the question immediately.

How to use it

reorder(category, value) sorts smallest first and reorder(category, -value) largest first. coord_flip() lays a vertical chart on its side, and factor(levels = ) fixes a fixed order such as the calendar.

What happensillustration

1Largest first

ggplot(by_district, aes(x = reorder(district, -confirmed), y = confirmed)) + geom_col(fill = "steelblue") + labs(x = NULL, y = "Confirmed cases")
Plots panefigure
Explanation
  • reorder(district, -confirmed) reorders the category by the number, and the minus sign makes it descending.
  • The order lives in the data, not in the drawing, which is why reorder() goes inside aes().
  • fct_reorder(district, confirmed, .desc = TRUE) from forcats does the same thing and reads more clearly in long code.

2Smallest first

ggplot(by_district, aes(x = reorder(district, confirmed), y = confirmed)) + geom_col(fill = "steelblue") + labs(x = NULL, y = "Confirmed cases")
Plots panefigure
Explanation
  • Drop the minus sign and the same code sorts ascending.
  • Ascending order suits a chart about what is lowest, coverage gaps, or the districts reporting least.
  • Western Rural sits lowest here because it has only four chiefdoms, not because malaria is rare. Row counts and totals are not the same thing.

3Sorted and horizontal: the readable default

ggplot(by_district, aes(x = confirmed, y = reorder(district, confirmed))) + geom_col(fill = "steelblue") + labs(x = "Confirmed cases", y = NULL)
Plots panefigure
Explanation
  • On a horizontal chart the category is on y, so reorder() goes there too: and ascending puts the largest bar at the top, because y counts upwards.
  • This combination: summarised, sorted, horizontal, is the one to reach for by default with district or chiefdom names.
  • No rotated labels, no squinting: every name reads left to right.

4The old way: coord_flip()

ggplot(top6, aes(x = reorder(district, confirmed), y = confirmed)) + geom_col(fill = "steelblue") + coord_flip() + labs(x = NULL, y = "Confirmed cases")
Plots panefigure
Explanation
  • coord_flip() draws the chart vertically and then turns the whole thing on its side, which gives the same picture as swapping the mappings.
  • It still works and it is everywhere in older scripts, so you need to recognise it.
  • The catch is that x and y in the rest of your code still refer to the pre flip axes, which confuses labelling. Swapping the mappings avoids that.

5A fixed order: the calendar

ggplot(by_month, aes(x = month, y = confirmed)) + geom_col(fill = "steelblue") + labs(x = NULL, y = "Confirmed cases", title = "Order comes from the factor levels, not from the values")
Plots panefigure
Explanation
  • Months must not be sorted by size, the story is the shape over time, so the order is fixed.
  • That order comes from factor(month, levels = month.name), done back on card 00. ggplot2 simply follows the levels.
  • Rule of thumb: sort by value for categories, keep the natural order for anything with a sequence, months, weeks, age groups, quarters.

When to use it

The last five minutes before a chart leaves your machine. A chart that goes into a bulletin needs a title, readable labels, honest axes and a saved file at the right size.

How to use it

geom_text() writes the values on the bars, labs() supplies the words, theme_minimal() and theme() handle the look, and ggsave() writes the file.

What happensillustration

1Put the number on the bar

ggplot(by_month, aes(x = month, y = confirmed)) + geom_col(fill = "steelblue") + geom_text(aes(label = confirmed), vjust = -0.4, size = 3.2) + labs(x = NULL, y = "Confirmed cases")
Plots panefigure
Explanation
  • geom_text() draws one label per row; aes(label = confirmed) says which column to write.
  • vjust = -0.4 lifts the text just above the bar. Positive values push it down inside the bar instead.
  • Labels remove the need for the reader to trace a bar back to the axis, worth it whenever there are fewer than about a dozen bars.

2Colours you chose

ggplot(by_month, aes(x = month, y = confirmed, fill = month)) + geom_col() + scale_fill_brewer(palette = "Blues") + labs(x = NULL, y = "Confirmed cases") + theme(legend.position = "none")
Plots panefigure
Explanation
  • scale_fill_brewer() gives you a designed palette instead of the ggplot2 defaults; scale_fill_viridis_d() is the colour blind safe alternative.
  • Mapping fill = month when the x axis is already month adds no information, so the legend is switched off with theme(legend.position = "none").
  • For a single series, one fixed colour is usually better than a palette. Save colour for a variable that actually splits the data.

3Words, and labels that fit

ggplot(by_district, aes(x = reorder(district, -confirmed), y = confirmed)) + geom_col(fill = "steelblue") + labs(title = "Confirmed malaria cases by district", subtitle = "January to June 2026, routine facility reports", caption = "Source: routine_cases_dummy.csv", x = NULL, y = "Confirmed cases") + theme_minimal() + theme(axis.text.x = element_text(angle = 45, hjust = 1))
Plots panefigure
Explanation
  • labs() holds every piece of text: title, subtitle, caption and axis names. Say the period and the source in the subtitle and caption, a chart travels without you.
  • angle = 45, hjust = 1 turns long category labels so sixteen districts fit. The alternative, and often the better one, is horizontal bars.
  • theme_minimal() drops the grey panel. Pick one theme and use it for every chart in a report.

4Honest axes

ggplot(top6, aes(x = reorder(district, -confirmed), y = confirmed)) + geom_col(fill = "steelblue") + scale_y_continuous(limits = c(0, 9000), breaks = seq(0, 9000, 3000), labels = scales::comma, expand = expansion(mult = c(0, 0.05))) + labs(x = NULL, y = "Confirmed cases")
Plots panefigure
Explanation
  • A bar chart must start at zero. Cutting the axis makes small differences look enormous, and it is the single most common way a chart misleads.
  • breaks chooses the gridlines, labels = scales::comma turns 8039 into 8,039, and expand removes the gap under the bars.
  • Set limits deliberately when you want several charts in a report to share one scale.

5Save it at a size you can use

p <- ggplot(by_district, aes(x = confirmed, y = reorder(district, confirmed))) + geom_col(fill = "steelblue") + labs(title = "Confirmed cases by district, January to June 2026", x = "Confirmed cases", y = NULL) + theme_minimal() ggsave("cases_by_district.png", plot = p, width = 8, height = 5, dpi = 300) list.files(pattern = "png$")
R Consoleoutput
[1] "cases_by_district.png"
Explanation
  • Assigning the chart to p lets you save it, reuse it and add layers later without redrawing everything.
  • ggsave() takes the size in inches and the resolution in dpi. 8 by 5 at 300 dpi drops straight into a Word report; the default 72 dpi looks blurred.
  • The extension decides the format: .png for documents, .pdf for anything that will be printed or resized.
